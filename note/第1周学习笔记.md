## 第 1 课：Agent 原理与 ReAct 框架

### 1. Agent 的定义

```
Agent = LLM（大脑）+ Harness（手和脚）
```

| 组件 | 作用 | 项目实现 |
|------|------|---------|
| 感知(Perception) | 获取环境信息 | 用户输入、工具返回 |
| 思考(Reasoning) | 推理决策 | LLM 意图分类、规划 |
| 行动(Action) | 执行工具调用 | MCP 工具调用、API 调用 |
| 记忆(Memory) | 存储历史信息 | 短期对话 + 长期画像 |

### 2. ReAct 框架

```
思考(Think) → 行动(Act) → 观察(Observe) → 思考(Think) → ...
```

### 3. Audit-AIOPS 的线性 ReAct

文件：`Audit-AIOPS/app/agent/orchestrator.py`

```python

**设计亮点**：

- **审批对齐**：`needs_approval=True` → 自动触发双人审批 + Checkpoint

### 4. 刷题教练的图式 ReAct（StateGraph）

文件：`shuati-coach/server/agent/orchestrator.py` + `supervisor.py`

```
        ┌──────────┐
        │ classify │ ← Supervisor 意图分类
        └────┬─────┘

     ▼       ▼       ▼          ▼

                    ▼

               └────────┘
```

**StateGraph 引擎** (`supervisor.py`)：LangGraph 同构轻量实现，生产可一键迁移：

```python
class StateGraph:
    def add_node(self, name, func): ...       # 注册节点
    def add_edge(self, src, dst): ...          # 固定边
    def add_conditional_edges(self, src, router, path_map): ...  # 条件边
    def set_entry_point(self, name): ...       # 入口
    def set_finish_point(self, name): ...      # 终点
    def compile(self): ...                     # 编译

class CompiledGraph:
    async def invoke(self, state):
        cur = self.entry
        while cur != END:
            update = await self.nodes[cur](state)  # 执行节点
            state.update(update)
            if cur in self.conditional:
                choice = router(state)             # 条件路由
                cur = path_map[choice]
            elif cur in self.edges:
                cur = self.edges[cur]               # 固定边
        return state
```

### 5. 两种编排对比

| 维度 | Audit-AIOPS | 刷题教练 |
|------|------------|---------|
| 模式 | 线性 ReAct | 图式 ReAct (StateGraph) |
| 路由 | 代码 if-else | 条件边 (conditional_edges) |
| 节点数 | 隐式（3步） | 显式（6节点） |
| 记忆 | 简单短期 | 三层记忆 + 六段式上下文 |
| 审批 | 双人审批 + Checkpoint | 无（C端产品） |
| 扩展 | 加技能到 registry | 加节点到 graph |

### 6. 面试话术

> "我的 Agent 编排有两种模式：Audit-AIOPS 用线性 ReAct，一次对话走完整条链路（意图识别→拆单→审批路由）；刷题教练用 StateGraph（LangGraph 同构），六节点 classify→子Agent→reflect，条件边按意图路由。关键设计原则是**Agent 做薄、复杂度放 harness**——编排层只调度，能力通过 Skill/MCP 插件注入。"

### 4. 虚拟工具范式（Ghost Tools）

`call_llm_tool()` — 来自 HKUDS nanobot 的关键技巧：

```python
async def call_llm_tool(system, user, tool_name, tool_schema):
    payload = {
        "tools": [{"type": "function", "function": {"name": tool_name, "parameters": tool_schema}}],
        "tool_choice": {"type": "function", "function": {"name": tool_name}},
    }
    # 用 Function Calling 约束输出结构，但不真正执行工具
    # 只截获 tool_calls[0].function.arguments 作为 JSON 结果
```

**为什么不用 `response_format=json_object`？** 很多厂商对 json_object 支持不稳定（返回带 ```json 包裹），而 Function Calling 对参数有严格 JSON 约束，所有 OpenAI 兼容端点统一支持。

### 5. 双层缓存系统

文件：`Audit-AIOPS/app/llm/cache.py`

**第一层：PromptCache（精确命中）**
```
(provider, system, user) → SHA256 → OrderedDict 查找
相同提示直接复用 → 等价于推理端 KV Cache 前缀复用
```

**第二层：SemanticCache（语义命中）**
```
用户输入 → 本地 Embedding（字符级哈希词袋）→ cos 相似度 ≥ 阈值 → 复用
"Ukey怎么申请" ≈ "如何申请制作一个Ukey"
```

**组合策略**：`LLMCache.get()` → 先精确、后语义，命中后统计 `saved_ms_total`。

### 4. 六段式上下文预算

文件：`shuati-coach/server/agent/memory.py`

```python
BUDGET = {
    "identity": 240,   # 系统身份
    "profile": 420,    # 长期画像
    "summary": 520,    # 诊断摘要
    "short": 1500,     # 对话历史
    "history": 380,    # 中长期事件日志
    "current": 1100,   # 当前消息

# 总预算 ~3800 字符 ≈ 1.3k token

def build_context(self, message, tool_summary=""):

        f"[身份] {identity}\n"
        f"[长期画像] {profile}\n"
        f"[诊断摘要] {summary}\n"
        f"[对话历史] {short}\n"
        f"[近期事件] {history}\n"
        f"[当前] {current}"

```

**设计理念**：每一段都有明确的 token 预算上限，`_truncate()` 按远段优先丢弃。这是防御 **Context Rot**（上下文腐烂）的核心机制 —— 指令不会随对话增长而衰减。

### 2. Audit-AIOPS 的混合检索

文件：`Audit-AIOPS/app/services/retrieval_hybrid.py`

这是项目的检索核心，包含 **5 个检索器**：

```
HybridRetriever（统一入口）
├── KeywordRetriever    # TF-IDF 关键词检索（稀疏召回）

```

**防幻觉机制**（核心设计）：
```
相关性不足 → relevant=False → 明确拒答：
"抱歉，我在知识点库和你的错题里没找到足够相关的资料，

```

**RAG 问答全链路**（tools.py `rag_qa`）：
```
用户问题 → KnowledgeRetriever.search()
    → 相关性不足 → 拒答
    → 相关性充足 → 拼接引用 → LLM 生成（要求标注引用号[n]）
    → 记录到评测日志（eval.log_interaction）
```

| 多模态 | 截图/表格跨模态召回 | 无 |
| 防幻觉 | 低相关拒答 | 2-gram 关键词硬约束 |
