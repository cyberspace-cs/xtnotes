# Claude Code / 智能体编程经验

> 我用代理式编程（agentic coding）工具（Claude Code 类 / CodeBuddy）做开发，这里记工作流与踩坑。核心：**把 AI 当能跑命令、读代码、改文件的协作者，而不是聊天机器人。**

---

## 1. 心智模型转变

| 旧方式 | 新方式 |
|--------|--------|
| 问 AI 一段代码，自己复制 | 让 AI 直接改文件、跑命令、看结果 |
| 一次问一个问题 | 给目标，AI 自主多步执行 |
| 自己查文档 | AI 读仓库 + 检索，给我结论 |

## 2. 我的高效工作流

### 2.1 先给上下文，再下指令
- 让它先 `read_file` / 搜索仓库，理解结构。
- 指令要具体到「改哪个文件、实现什么、约束是什么」，别模糊。

### 2.2 大任务拆小
- 用 **TODO 列表**把多步任务拆成可勾选项。
- 复杂改动让它**先出计划再执行**（plan mode 思想）。

### 2.3 子代理并行（team 模式）
- 多个独立子任务（读 A 模块 / 写 B 模块 / 查 C  bug）并行派给子代理。
- 主代理只汇总，不承载中间过程 token。

### 2.4 自动化与 Hooks
- 重复操作（格式化、跑测试、lint）交给自动化 / hook。
- 让 AI 在改完代码后**自动跑 lint / 测试**再交付。

## 3. 踩过的坑

- ❌ 指令太泛 → AI 改错文件。✅ 给绝对路径 + 明确边界。
- ❌ 大文件整段重写 → 丢改动。✅ 用 targeted edit（局部替换）。
- ❌ 不问就自动跑危险命令。✅ 危险操作要确认，git 改动随时可回退。
- ❌ 上下文丢光重来。✅ 用 memory / 项目说明文件沉淀长期上下文。

## 4. 和我的 Agent 项目相通的点

- **编排思想一致**：Claude Code 的「计划→执行→反思」≈ 我的 StateGraph（classify→plan→reflect）。
- **工具替代生成**：能脚本化的别让 LLM 生成（0 token 思想）。
- **上下文预算**：代理式编程也吃上下文，压缩/缓存同样重要（我的 `compress_context`、`KVCacheManager` 可类比）。

## 5. 给新人的 3 条建议

1. **从「改文件」而不是「问代码」开始**，体验到代差。
2. **大任务务必先计划**，别让 AI 盲改。
3. **善用子代理和自动化**，把重复活外包出去。
